# MedGuardian AI — Clickable MVP

A Python (Streamlit) prototype of the MedGuardian AI product proposal: a medication
adherence & interaction copilot, themed in the **Sandoz blue palette**
(`#0A53BE` Denim / `#94BFE7` Cornflower / `#001C4A` Prussian Blue / `#A8D5FF` Anakiwa).

## What's in this MVP

| Page | What it demonstrates |
|---|---|
| 🏠 Patient Dashboard | The client's home view — medication list, adherence chart, add-a-medication interaction check |
| 💬 AI Copilot | **Client experiences the AI directly** — a chat interface answering medication/interaction questions |
| 🧑‍⚕️ Pharmacist Review Queue | The human-in-the-loop MVP design from the proposal — moderate/high-risk alerts are held for pharmacist approval before reaching the patient |
| 🩺 Physician View | **Specialty Pharma Extension** (proposal Section 13) — closes the loop with the prescriber, not just the pharmacist, for a specialty-drug care program |
| 📊 KPI Dashboard | Live view of the Metrics Framework (adherence rate, alerts acted on, false-positive rate, retention, review turnaround) |
| 🏭 Pharma Program Insights | **Specialty Pharma Extension** — de-identified, aggregate program metrics for a pharma manufacturer's patient support program team, with a one-click AI summary for medical affairs |
| 🗂️ AI for Project-Management Artifacts | AI-generated status summaries of the product's own **roadmap, risk register, and backlog** — one click turns structured PM data into a stakeholder-ready narrative |

## Run it

```bash
pip install -r requirements.txt
streamlit run app.py
```

Then open the local URL Streamlit prints (usually `http://localhost:8501`).

## The AI layer

`ai_engine.py` is pluggable:

- **With a real key:** set `ANTHROPIC_API_KEY` in your environment and the AI
  Copilot and the PM-artifact summaries will be generated by a live Claude model
  (`MEDGUARDIAN_MODEL` env var to override the model name — check your account's
  available models at the time you run this, since model names change).
- **Without a key (default):** falls back to a deterministic, rule-based
  "simulated AI" so the whole MVP is demoable offline with no credentials —
  useful for a classroom/grading environment.

Both paths run through the **same** interaction-safety check
(`mock_data.check_interactions`), so switching between simulated and live AI
never bypasses the human-in-the-loop pharmacist review for moderate/high-risk
alerts — this mirrors the staged-automation MVP strategy in the product proposal.

## Important limitations (by design, for a course MVP)

- `mock_data.py` is a small, hand-picked set of medications/interactions for
  demo purposes — **not** a live DrugBank/RxNorm/openFDA integration and
  **not** for real clinical use.
- Adherence history, the review queue, and KPI numbers are simulated/seeded,
  not connected to a real backend or database.
- No authentication, encryption, or regulatory controls are implemented —
  those are out of scope for a UX/interaction prototype and are called out as
  open items in the Risk Assessment section of the product proposal.

## File structure

```
app.py          Streamlit UI, navigation, Sandoz-blue theme

```
